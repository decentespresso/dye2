# AI Repository Map

Use this file for orientation. Read the smallest matching topic note, inspect the named
source, and widen only when the task crosses a boundary. **Do not preload all notes.**

DYE2 is a plugin for Decaid (the Decent Espresso tablet software). It manages beans, roast
batches, grinders and equipment, and adds a shot dashboard, auto-favourites and recipe
editing on top of the stock DYE workflow.

## The One Thing To Know First

The repo has **two runtimes, and the split runs through files rather than between them.**
`dye2-plugin/src/` is TypeScript that runs inside `flutter_js` with no DOM and no `fetch`,
acting as a server-side HTML renderer. The browser-side JavaScript it serves lives in the
same files as exported **template-literal strings**, which are inert until the WebView
parses them — so they get no type checking and no build error.

If you are about to edit anything under `dye2-plugin/src/`, read `AI_RUNTIME_NOTES.md`.

## Production Entry Points

- `dye2-plugin/src/plugin.ts` — `PluginInstance` and the `__httpRequestHandler` route switch.
  The whole plugin surface is one `switch`.
- `dye2-plugin/src/utils/dev-shell.ts` — the shell every live page is built with, plus the
  scaling and keyboard-avoidance scripts.
- `dye2-plugin/src/utils/dev-api.ts` — all browser-side bridge access, as a string.
- `dye2-plugin/src/pages/*.ts` — one module per route; each holds both runtimes' code.
- `dye2-plugin/manifest.src.json` — plugin identity, permissions, and the declared route list.
- `dye2-plugin/dev-server.mjs` — local host + bridge proxy.

## Read Late, Not First

- `dye2.reaplugin/` — **generated build output**, committed. Never edit by hand; rebuild.
- `dye2-plugin/src/styles/tailwind.generated.css` — generated by `npm run build:css`.
- `dye2-plugin/src/vendor/plotly-basic.min.js`, `dev/plotly-3.1.0.min.js` — vendored bundles,
  two separate copies for the two page families.
- `BeanconquerorTestData.json` — import fixture, not app data.
- **Dead code, zero importers — do not copy or extend:** `dye2-plugin/src/components/` (an
  abandoned Web Component experiment, the only `customElements.define` in the tree),
  `dye2-plugin/src/api/client.ts`, and all of `dye2-plugin/src/pages/layout.ts` (both
  `pageShell()` and `sharedStyles()`). Older docs described these as the house style. They
  are not.
- `DYE2_REDESIGN_PLAN.md`, `AUTOFAV_DASHBOARD_PLAN.md` — historical intent and design specs.
  Useful for *why* and for Figma measurements; not evidence of what the code does now.
- `MANUAL.md` — user manual. `README.md` — user and plugin-developer docs. Neither is an
  implementation reference.
